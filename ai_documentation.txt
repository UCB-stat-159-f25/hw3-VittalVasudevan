import numpy as np

def test_whiten_simple():
    sig = np.sin(np.linspace(0, 2 * np.pi, 100))  # full sine wave
    fsig = whiten(sig)

    # Make sure something is returned
    assert fsig is not None

    # Check mean ~ 0
    assert np.abs(np.mean(fsig)) < 1e-10, f"Mean not zero: {np.mean(fsig)}"

    # Check variance ~ 1
    assert np.abs(np.var(fsig) - 1) < 1e-10, f"Variance not 1: {np.var(fsig)}"

    # Optional: Check autocorrelation at lag 1 is small
    autocorr = np.corrcoef(fsig[:-1], fsig[1:])[0, 1]
    assert np.abs(autocorr) < 0.2, f"Autocorrelation too high: {autocorr}"

Prompt: "Fix my Makefile error '/bin/sh: 0: Illegal option -o pipefail'."

Output: Ah! That error happens because your Makefile is trying to use set -o pipefail, which is a bash-specific option, but your Makefile is being run with /bin/sh (the default shell for Make on many systems, e.g., Debian/Ubuntu). /bin/sh doesn’t support pipefail.

Here are ways to fix it:

Option 1: Force Make to use bash

Add this at the top of your Makefile:

SHELL := /bin/bash
.SHELLFLAGS := -eu -o pipefail -c


SHELL := /bin/bash → use bash instead of sh

.SHELLFLAGS := -eu -o pipefail -c → pass pipefail safely to bash

This allows you to keep set -o pipefail behavior in your recipes.

Option 2: Remove pipefail usage

If you don’t need pipefail, just remove the set -o pipefail line from your Makefile recipes:

# instead of
# set -o pipefail; my_command | other_command
# just write
my_command | other_command


Downside: if a command in a pipeline fails, make may not detect the error.

Option 3: Use || exit for pipelines

If you want safer error handling without pipefail:

my_command | other_command || exit 1


This will exit if the last command in the pipeline fails.

Less robust than pipefail but portable in /bin/sh.

💡 Recommendation:
Use Option 1 if you want bash features (pipefail, set -e) reliably. Most modern Makefiles do this at the top.
